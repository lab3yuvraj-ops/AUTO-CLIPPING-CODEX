# Browser-assisted onboarding contract

The trigger is **onboarding** in the student's own clone. This is an instruction for the Codex operator, not a standalone browser robot. Keep the existing clipping/review/render/publishing behavior unchanged. The repository does not bundle Codex or guarantee browser-control capabilities on another installation.

## Execute setup

1. Read AGENTS.md and ONBOARDING.md. Inspect tool availability and existing setup without printing secrets. Ask for the student's channel if they want channel lookup, and whether to connect Instagram now or clip supplied URLs only. Instagram credentials are not a clipping prerequisite. Explain that HF access is for local model downloads, not hosted inference.
2. Install missing Python 3.11, Git, FFmpeg/ffprobe, Node.js and the documented CPU-only Python environment using available authorized installation mechanisms. Preserve existing `.env` and unrelated settings. Run `reel.py doctor`; it checks, it does not install. Follow its actual failures rather than assuming setup succeeded. No paid services, CUDA, dashboard or scheduler.
3. Open Chrome using supported browser/computer-use tools; read that tool's skill and confirmation requirements first. Check Chrome is available. If Chrome or browser control is unavailable, say exactly which capability is missing and give the smallest manual alternative; never claim navigation was automated. Use only task-relevant official account pages, not password stores or unrelated browser profiles.
4. Open https://huggingface.co/pyannote/speaker-diarization-community-1. Let the student complete sign-in, 2FA/CAPTCHA and personally accept any model terms/contact sharing. Do not click acceptance of those terms for them. If access is pending or denied, report that state; a token does not grant gated-model access by itself.
5. Open https://huggingface.co/settings/tokens. Prefer an existing suitable private `HF_TOKEN`. Otherwise help create a clearly named read-only token for this automation, with the least scopes the current official UI requires to download the approved model. Do not create write/admin tokens or change billing. Perform routine permitted clicks rather than telling the student to do each click. Observe actual UI state; do not assume its layout or scopes.
6. Store the token in the ignored local `.env` only through a supported private transfer that does not echo it into chat, tool results, screenshots, ordinary logs or command arguments. If that is not supported, have the student paste it directly into the local `.env` editor or a hidden terminal prompt. Do not dump the clipboard, browser storage or full `.env`. Never present private credentials as a completion artifact. Verify success by model loading, not by printing the token.
7. Run `.venv/Scripts/python.exe reel.py prepare-models --download` after access and local token setup. Then run `.venv/Scripts/python.exe reel.py prepare-models` and `reel.py doctor`. Explain any actual unresolved dependency/model errors. Base/tiny selection fallback weights may provision on first use; include that in setup timing. Preserve cached weights for later runs.
8. If Instagram setup was requested, open the student's own Zernio account connection flow and assist with the existing Instagram authorization. Use only permissions necessary for the requested connection. The student completes provider-required login/consent; routine permitted navigation/authorization may be handled by Codex when covered by the student's explicit connection request and tool rules. Do not create/upgrade a paid plan. Store the student's Zernio API key privately and identify the connected Instagram account `_id`; never copy the creator's values. Verify through the existing onboarding command. No test post.
9. Do not request YouTube credentials by default. If a real challenge occurs, guide the student to an authorized local cookie file. If appropriate, use the documented optional local PO-token helper; do not enable paid proxies or export another person's cookies.
10. Summarize installed tools, offline model-check results, connection status and remaining actions, without credentials. Then accept a YouTube URL, ask clip count, and use the latest one-pass review workflow. Publication still needs approval of the exact finished preview.

## What the student must do

Codex handles routine navigation, installation commands, configuration and checks where its tools support them. It should not repeatedly request confirmation for already authorized routine steps. However, **zero clicks is not guaranteed**: the student controls their own login/passwords, second factors, CAPTCHA, gated-model terms/contact-sharing consent, provider-required personal authorization and any mandatory OS/tool approval. Stop only the dependent step, explain the exact requirement and continue after it is completed. Never claim authorization or model access succeeded until verified.

Onboarding does not authorize payment, broader account access, bypassing a challenge, publication, or credential sharing. If credentials were exposed accidentally, stop exposing them and guide the student to revoke/replace the affected credential privately.
